# 원고·이미지 작성 기준

현재 production 기본 프로필은 v89입니다. v89의 임시저장 전용·표 이미지 전용 규칙은 사용자가 요청한 실제 발행·네이버 표 유지 방향으로 변경했습니다. 기존 원고와 해당 ID의 완성 이미지는 우선 재사용합니다.

## 내용

- 보통 4,000~5,000자 안팎에서 독자 질문에 충분히 답합니다. 분량을 채우기 위한 반복은 피합니다.
- 자동 검사는 공백 제외 2,600자, 소제목 6개 이상, 사례와 질문·답변 포함 여부를 최소 기준으로 삼습니다. 글자 수만 통과해도 법령 검증이나 내용 검수가 끝난 것은 아닙니다.
- 도입의 실제 고민 → 지출·계약의 분류 → 계산 사례 → 적용 조건과 예외 → 증빙·실행 체크리스트 → FAQ → 상담이 필요한 조건 순서로 설명합니다.
- 계산에는 적용연도, 가정한 금액·기간·방법을 표시합니다. 예시 내용연수를 실제 법정 내용연수처럼 표현하지 않습니다. 필요경비와 절세액·환급액을 구분합니다.
- 공식 법령·국세청 자료를 작성 시점에 다시 확인하고, 출처와 확인일은 별도 내부 검토 기록에 보관합니다. 공개 글에는 ‘확인한 법령과 적용 기준’ 등의 법령·출처 부록을 넣지 않습니다.
- 공개 글은 상담을 위한 마케팅 원고입니다. 독자의 고민, 구체적인 가상 사례, 준비자료와 판단이 달라지는 조건을 충분히 설명하고 마지막에 명함의 연락처로 상담을 요청하도록 안내합니다. 실적·무료상담·절세 보장 등 확인되지 않은 영업 사실을 만들지 않습니다.

## 이미지·명함

2026-11-01 사용자 정정이 기존 V3 문서보다 우선합니다. 실제 기준은 다운로드 폴더의 `이미지 형식 1.png`와 `이미지 형식 2.png`입니다. 대표는 초록·크림색의 풍부한 인물 일러스트와 굵고 둥근 한글 제목, 본문은 같은 화풍의 그림 비교·설명형을 사용합니다. 두 예시의 가로 3:2 비율을 따릅니다. 글자만 있는 사각 카드·문서형 슬라이드로 임의 대체하지 않습니다. 이미지 생성은 예시를 참조해 built-in ImageGen을 사용하고 결과를 실제로 열어 검수합니다. 기존 `illustrations.js`의 카드형 출력은 현재 블로그 이미지 제작에 사용하지 않습니다.

- 대표 1장과 본문 5장 이상을 해당 주제에 맞춰 준비합니다. 설명과 이미지를 교대로 배치하고 같은 이미지를 중복 계산하지 않습니다.
- 다른 콘텐츠 ID의 이미지를 대신 사용하지 않습니다. 해당 주제의 기존 완성 이미지는 유지합니다.
- 자동으로 마지막에 원본 `office_contact.jpeg`를 붙입니다. 명함 뒤에는 원고·태그·출처를 넣지 않습니다.
- PNG와 JPEG를 원본 그대로 업로드합니다. 명함의 이름·전화번호·주소를 재생성하지 않습니다.
- 발행 전후 이미지 개수, 문장 대비 삽입 순서, 맨 끝 명함의 위치·비율을 확인합니다.

## 자연스러운 상담 안내

- 본문 중간마다 ‘상담을 요청해 주세요’, ‘자료를 준비해 주세요’를 반복하지 않습니다. 고민과 해결에 필요한 판단을 먼저 설명하고 마지막 한 단락에만 상담으로 연결합니다.
- ‘내 상황에 맞는 상담을 준비하세요’ 같은 공통 영업 소제목과 문의 양식처럼 긴 준비자료 나열을 마무리에 넣지 않습니다.
- 각 주제에 맞춰 실제 사람이 말하듯 씁니다. 예: ‘부모님께 받을 돈을 차용으로 할지, 증여로 할지 고민되시나요? 지원 금액과 자녀분의 상환 계획을 보고 어떤 방법이 맞을지 안내해 드리겠습니다. 궁금한 점은 아래 연락처로 문의 주세요.’
- 같은 마무리를 모든 글에 복사하지 않고 병의원·상속주택·미수금 등 독자의 고민에 맞춰 짧게 씁니다. 무료상담·확정 절세·성공률 등 확인되지 않은 약속은 만들지 않습니다.

## 주제별 카테고리

| 주제 | 실제 카테고리 | 번호 |
|---|---|---|
| 양도·상속·증여·차용증·주택자금 | 양도·상속·증여 | 13 |
| 병의원·치과·한의원·개원·의료 | 병·의원 | 11 |
| 법인·임원퇴직금·가지급금 | 법인 | 12 |
| 개인사업자·쇼핑몰·법률사무소·프리랜서·유튜버 | 사업자 | 10 |
| 일반 세무 주제 | 세무사 | 8 |

산업/주제/제목으로 분류하고 실제 발행 설정 창에서 선택 결과를 확인합니다. 블로그 카테고리 구성이 바뀌면 매핑을 업데이트해야 합니다.

## 기존 글 보강

`action=update`, 정확한 target_url과 expected_title을 지정합니다. 최초 게시 이력이 있으면 supersedes_id로 연결합니다. 기존 본문을 백업하고 같은 글의 편집 화면에서만 교체합니다. 업데이트 결과 글 번호가 바뀌면 성공 처리하지 않습니다. 기본적으로 기존 글의 공개 설정을 유지합니다.
