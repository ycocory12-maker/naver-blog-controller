## 2. 정책 충돌 — P0

사용자 승인된 범위는 **Work1 기획 → Work2 원고 → Work3 원본 이미지 → Work4 네이버 임시저장 후 재열기 검증**이며 **자동 발행 금지**입니다.

그런데 v3의 실제 코드와 문서에서는 다음이 확인됩니다.
- `publish-v3/README.md`: "네이버 실제 발행 컨트롤러 v3", `mode: "publish"` 예시, `PUBLISHED` 상태, 실제 발행 URL 관리.
- `publish-v3/naver.js`: `saveDraft()`는 `draft_mode_not_calibrated_use_publish` 오류를 발생시키므로 임시저장 기능을 구현하지 않음. `preparePublication()`은 발행 버튼을 클릭.
- `publish-v3/server.js`: `POST /scheduler/run`은 `scheduler.publishDue()`를 호출. `/jobs/:id/verify`는 `PUBLISHED` 상태에서만 작동.
- `naver-daily-publish` 서비스는 실제 cron이 설정돼 있고 11/03~11/06 기간 publisher HTTP에서 `POST /scheduler/run` 14회(200) 확인.
- publisher HTTP에서 `POST /jobs`, `POST /jobs/:id/retry`, `POST /jobs/:id/verify`, `GET ...-published.png`가 관찰됨. **요청 성공/파일명만으로 각 글이 실제 공개 발행되었다고 확정할 수 없음.** 다만 실제 발행 경로가 존재·호출된 것은 확인됨.

**즉시 조치 제안(운영 변경은 승인 후):** 스케줄러의 발행 실행 경로를 중지/비활성화하고, v3에서 `mode=publish`·`PUBLISHED` 경로를 사용하지 않도록 차단. 기존 공개 글이 존재하는지는 게시물 URL 및 `PUBLISHED` 레코드를 **읽기 전용**으로 확인. 게시물을 임의 삭제·수정하거나 다시 발행하지 말 것.
