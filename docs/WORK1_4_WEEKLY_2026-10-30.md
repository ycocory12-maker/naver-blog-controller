## 2. 이번 주 실패·재시도·위험

1. **P0 runtime 상태 조회 404 (반복):** Relay는 `/runtime-status`를 라우팅하지 않습니다. GitHub main의 `GET /work4/runtime-status`는 배포되지 않았습니다. 기존 7일 HTTP 404 16회.
2. **P0 비원자적 중복 방지:** 런타임 GET을 추가하더라도 순간 조회만으로 원자적 잠금이 되지 않습니다. POST 전 충돌 방지·idempotency가 필요합니다.
3. **P0 임시저장 완료 판정:** PR #2의 Work4 완료 게이트를 `draft_reopen_verified=true` 필수로 강화하는 코드 수정. 실제 브라우저 E2E 검증 전에는 **미배포·미검증**.
4. **P0 PR 병합 충돌:** main이 10/24 별도 runtime route를 추가해 PR #2와 차이가 생겼습니다. 현재 `mergeable=false`. main 기반으로 수동 재정합 및 검토 필요.
5. **P1 영속성·자동 연결:** controller `/tmp` 상태파일·볼륨 0개·다음 Work 트리거 변수 없음. 배포 SUCCESS로 해결되지 않음.
6. **P1 세션/응답 회수:** 10/30 039 개별 draft 응답과 `/status`, `/pipeline-status` 내용은 회수되지 않아 확인 불가. 활성 세션을 덮어쓰지 않았습니다.
